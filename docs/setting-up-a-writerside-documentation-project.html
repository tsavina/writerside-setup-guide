Setting Up a Writerside Documentation Project

Learn how to create, build, and publish a Writerside documentation project.

Prerequisites

Before you begin, make sure you have the following:

  • IntelliJ IDEA (Community Edition is sufficient)

  • Git installed on your machine

  • A GitHub account

Step 1: Install the Writerside plugin

  1. In IntelliJ IDEA, go to File | Settings | Plugins and open the Marketplace tab.

  2. Search for Writerside.

  3. Click Install, then restart the IDE when prompted.

After the restart, you will see a Writerside pane in the left sidebar. This confirms the plugin is active.

Step 2: Create a new documentation project

  1. Go to File | New Project.

  2. Select Writerside on the left, then select Starter Project, and click Next.

  3. Specify the name and location for your project and click Create.

When the project opens, you'll see the Writerside tool window on the left with your instance (your documentation site). The Table of Contents pane contains the starter topic. The editor opens in the center, and the preview opens on the right.

Step 3: Add a new topic

Topics are the individual pages of your documentation. Writerside supports both Markdown and XML. This guide uses XML topics: they support semantic elements and content reuse, which help as your docs grow.

  1. In the Table of Contents pane, click +.

  2. Select Empty XML Topic.

  3. Specify a title and filename for your topic.

  4. Write your content using semantic elements.

The default starter topic is a working example of common semantic elements. See the Semantic markup reference for the full list.

The preview opens automatically when you first open a topic. To reopen it, right-click any topic in the Table of Contents and select Preview Topic.

Step 4: Build the documentation locally

Run a local build to catch errors before publishing.

  1. In the Writerside tool window, right-click your instance and select Export To | Web Archive.

  2. Click Run.

  3. After the build completes, check the Run tool window for errors and warnings.

  4. Click Show generated files in the bottom-right popup to open the output directory.

  5. Extract the ZIP archive and open your topic's HTML file in a browser to preview it.

The Show generated files popup appears only immediately after the build. If you missed it, find the ZIP archive in your project's root directory, or run the build again.

Step 5: Push to GitHub

Push your source to GitHub to keep it version-controlled and shareable.

  1. In IntelliJ IDEA, go to Git | GitHub | Share Project on GitHub. If you don't see the Git menu, enable Git integration first in Settings under Version Control.

  2. Enter a repository name and uncheck Private. If prompted, authorize IntelliJ IDEA in your browser, then return to the IDE.

  3. Click Share. In the Add Files For Initial Commit dialog, select the files you want to track and click Add.

Verify your setup

To confirm everything works, check that:

  • Your project opens in IntelliJ IDEA with the Writerside tool window visible

  • Your topic renders in the preview pane without errors

  • A local build completes successfully

  • Your repository is visible on GitHub with all source files committed
